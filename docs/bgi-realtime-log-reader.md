# 茶包 BGI 实时日志独立读取接入说明

核对日期：2026-11-14。源码基准：`main-OldTeaBag-B191`，`0fca90ba709f12f04b4b9da2a4d9bb3649308a79`。

本文交付给开发独立小工具的新会话。目标只有：**不修改现有茶包 BGI、不启动助手，持续读取并及时显示 BGI 新产生日志；助手同时启动时，两者仍可各自工作。** 不要求 IPC，不引入房间、服务端、远程控制、任务调度或助手依赖。

## 1. 已核实的结论

当前助手嘟嘟可的**本机实时日志**来自 BGI 日志文件的增量读取，不是 BGI IPC。可直接沿用相同来源开发独立工具。

```text
茶包 BGI 的 Serilog 日志事件
  → <BGI 程序目录>\log\better-genshin-impactYYYYMMDD.log
      → 助手 BgiLogTailService → 嘟嘟可本机实时日志
      → 新工具自己的共享只读文件流 → 新工具实时显示
```

两个读取者各自保存文件偏移，互不消费对方的数据。BGI 写入端配置了 `shared: true`；助手以 `FileAccess.Read` 和 `FileShare.ReadWrite | FileShare.Delete` 打开文件。新工具使用相同的共享只读方式，不独占、不写回文件，即可与助手并存。这是当前源码的共享访问结论，本文未执行 BGI＋助手＋新工具的三进程实测；新工具尚未实现。

现有 BGI IPC 的 `ext.event.subscribe` 提供任务生命周期、进度和作业事件，没有完整原始日志事件。协调服务器的 `log.subscribe`、助手网页的 `log.poll` 属于另一层协议，依赖助手，不能用来满足“只开 BGI 和新工具”。本需求不需要连接这些通道。

## 2. 实时性：文件写入不会固定等几秒

### 2.1 BGI 写入端

当前 BGI 引用 `Serilog.Sinks.File 6.0.0`，直接配置 `WriteTo.File(...)`，未开启 `buffered: true`，也未在这条文件输出链外包异步日志队列。

该版本库的默认值是 `buffered: false`；其随包 README 说明默认逐事件 flush。这里的 flush 使数据可供其他进程读取，**不要求等待操作系统把缓存持久化到物理磁盘**。因此，文件跟随并不等于“等日志攒一批或程序退出后才能读”。

这不是硬实时承诺。BGI 线程调度、文件系统、磁盘异常、读取端调度、界面阻塞都可能增加延迟；也不能读取尚未被 BGI 生成或已被日志级别过滤的内容。

### 2.2 当前助手实际增加的等待

| 环节 | 当前助手实现 | 对时效性的含义 |
| --- | --- | --- |
| 发现新增字节 | `FileSystemWatcher` 的 Changed / Created / Renamed 唤醒读取线程 | 正常路径不必等到定时轮询 |
| 兜底检查 | 每 1000ms 轮询 | 监听通知丢失时仍会检查；不是严格最大延迟保证 |
| 多行事件收尾 | 看见下一条日志头时发出上一条；停写约 2 秒时发出最后一条 | 即使字节已经可读，最后一条结构化事件也可能暂不显示 |
| 界面刷新 | 200ms 合批 | 已解析事件再进入界面队列 |

因此助手当前显示也不是每条日志零延迟。没有新日志头到达时，最后一条可能等约 2 秒的空闲收尾，再加轮询、界面与调度等待。不能把 200ms 界面刷新间隔当作端到端延迟。

### 2.3 给新工具的时效性要求

以下是**新工具建议实现**，不是声称当前助手已经采用：

- `FileSystemWatcher` 唤醒 + 100～250ms 轻量兜底检查文件增长；目录重新枚举可以降低频率，避免每 100ms 扫描大量文件。
- 每次从自己的字节偏移读取新增内容，收到完整行即可交给显示层；不要等待下一条日志才首次显示上一条正文。
- 对结构化多行日志采用“当前事件可追加更新”：收到头行创建当前事件，后续正文/异常行更新同一事件；下一个头行封闭上一事件。不要把每次更新都重复新增为一条完整日志。
- 界面每 50～200ms 合批，文件读取在后台执行。没有界面的工具可在完整行到达后立即回调。
- 记录 `observedAt`（实际读到时间），不要只使用日志内 `time` 判断“刚收到”。读取开始前的历史明确标成历史，不作为刚发生的实时事件。
- 同一文件切换、截断、重连时清楚标识来源与缺口，不能把旧日志重播伪装成新日志。

这可以在相同来源上达到助手同等级的实时效果，并避免助手约 2 秒的多行收尾等待。具体延迟必须测量后报告，不能预先承诺固定的 10ms、100ms 或绝对不丢日志。

## 3. 日志目录和文件发现

### 3.1 目录

```text
<正在使用的 BetterGI.exe 所在目录>\log
```

BGI 写入基准是 `AppContext.BaseDirectory`，不是新工具当前工作目录，不是助手目录，也不是配置 `User` 目录。不要在工具中硬编码本仓库、开发机或旧源码路径。

优先让用户选择正在使用的 BGI 程序文件或日志目录，并保存在新工具自己的配置中。可选自动发现：枚举当前 Windows 会话的 BGI 进程，读取可执行文件路径，再定位同目录 `log`。权限不足时提供手动路径，不要把自动发现失败当作 BGI 不存在。

多套安装时必须选定一套，不能只按进程名任意取第一项，也不要递归扫描磁盘找“最新日志”。

### 3.2 文件名

BGI 配置的基础名称为 `better-genshin-impact.log`，按天滚动。助手兼容的文件名正则为：

```regex
^better-genshin-impact(\d{8})?(_\d{3})*\.log$
```

按大小写不敏感匹配，例如：

```text
better-genshin-impact20261114.log
better-genshin-impact20261115.log
better-genshin-impact.log
better-genshin-impact20261114_001.log
```

通常选日志目录内 `LastWriteTimeUtc` 最新的匹配文件。监听新建/改名与日期切换，同时定期重新发现目标。助手在当前文件近 5 秒仍有写入时暂不换目标，以免多实例交替写入导致不断重开和重复回填。

新工具若只支持一份文件，明确显示当前文件。若要求读取同一安装目录多个活跃文件，应为每个文件维护独立偏移和解析状态，再合并显示；这属于新工具实现选择，不能假定助手已经合并所有文件。

## 4. 文件读取约定

### 4.1 Windows / .NET 打开方式

```csharp
using var stream = new FileStream(
    path,
    FileMode.Open,
    FileAccess.Read,
    FileShare.ReadWrite | FileShare.Delete);
```

含义：新工具只读，允许 BGI 持续写入，允许助手或其他读取者同时打开，也不妨碍文件轮转/删除。其他语言也应使用等价的 Windows 共享标志；不要使用独占打开或默认拒绝写共享的封装。

新工具不用获取助手单例 mutex，不用助手配置根，不用助手房间身份，也不用注册为 BGI 子实例。配置、缓存及导出文件放在新工具自己的数据目录。

### 4.2 编码与增量

- UTF-8；当前日志库默认 UTF-8 无 BOM。新工具可兼容文件开头 BOM。
- 按字节偏移跟随，不能用字符数作文件偏移。
- 每次只读新增字节，例如每块 64KiB。不要每次读取整个文件。
- 保留末尾不完整行的字节，等后续补齐 LF (`0x0A`) 后再解码；或使用能跨块保留 UTF-8 状态的 Decoder。
- LF 与 CRLF 均兼容。中文多字节可能跨块，不要逐块独立解码后丢弃残余字节。
- 读到当前 EOF 表示“暂时没有新字节”，不是结束订阅。继续等待文件增长。
- watcher 回调只发唤醒信号，单个后台读取循环串行管理流、偏移和解析器，防止重复读取及并发状态错乱。
- 处理 watcher Error/缓冲溢出，以重新扫描和偏移对账恢复；定时检查不能省掉。

### 4.3 启动时从哪里读

两种模式必须分清：

1. **历史 + 实时**：首次回填文件尾部有限内容，再跟随新增字节。助手当前限制为最多 2MiB、最近 2000 行；新工具可采用同样上限，历史事件显式标记 `isHistory=true`。
2. **仅启动后的实时**：首次从当前 EOF 开始；若恰好处于未完行中间，后续残段不能误解析为一条完整新事件，可跳过该残行后再进入正常跟随。

回填截取点可能落在中文字符或事件正文中间：从第一个完整换行之后解析，保留未归属的残段或显式标识“历史起点截断”。不能把残段错误归入后一条事件。

## 5. 原始日志文本格式

BGI 当前文件模板：

```text
[{Timestamp:HH:mm:ss.fff}] [{Level:u3}] [{BgiInstance}] {SourceContext}{NewLine}{Message}{NewLine}{Exception}{NewLine}
```

示意（非实测采样）：

```text
[15:42:10.123] [INF] [Primary:S1:P12345:T1794650000000] BetterGenshinImpact.Example
开始执行任务

[15:42:10.456] [ERR] [Primary:S1:P12345:T1794650000000] BetterGenshinImpact.Example
任务执行失败
System.InvalidOperationException: 示例异常
   at Example.Run()

```

**头行与正文分行；不能把每个物理行都当成独立日志事件。** 遇到新头行时，上一事件结束；不匹配头行的行属于当前事件正文或异常，包括空行、堆栈和多行消息。

### 5.1 字段

| 字段 | 来源及处理 |
| --- | --- |
| time | 头行 `HH:mm:ss.fff`，本地时分秒。日期通常取文件名 YYYYMMDD；无日期文件名只能推断日期，应保留推断标识 |
| level | 常见 `DBG` / `INF` / `WRN` / `ERR`；保留未知级别原文，必要时显示归一化值 |
| instance | BGI 实例标识；当前写出形如 `Primary:S1:P12345:T...`、`ChildSession:S1:P...:T...`、`WebView(实例名):S1:P...:T...` |
| source | SourceContext，通常为类名，允许为空 |
| message | 多行正文 |
| exception | 可选，从正文识别疑似异常起始行及后续堆栈；分离属于启发式，必须保留原文 |
| sourceFile / fileOffset | 文件绝对路径与头行的字节偏移 |
| observedAt / isHistory | 新工具附加的接收时间、历史标记，不是 BGI 写出的字段 |

`S` 为 Windows 会话号，`P` 为进程号，`T` 为 BGI 日志身份构造时的 Unix 毫秒时间戳。不要把它们当成助手房间 UID、IPC 会话 ID 或每条日志的发生时间。

助手当前头行正则可作为旧格式兼容参考：

```regex
^\[(?<time>\d{2}:\d{2}:\d{2}\.\d+)\] \[(?<level>[^\]]{1,8})\](?: \[(?<instance>[A-Za-z][A-Za-z0-9]*:S\d+:P\d+:T\d+)\])?(?: (?<source>[^\r\n]+?))?\s*$
```

**不要原样当作当前所有实例格式的完整规范：** 当前 BGI 的 WebView 实例名带括号，上面助手正则的 instance 分组不覆盖它，可能落入 source。新工具应兼容当前写出格式及无实例段的旧格式，保留 `rawHeader`/`rawText`，遇到不认识的实例段也显示原文，不静默丢日志。不要把示例 `Primary` 或旧示例 `Main` 写死。

完整多行事件没有独立的长度或结束符。约 2 秒空闲封闭是助手的显示策略，不是日志格式规定。新工具采用可更新事件显示时，可及时显示正文，并在较晚续行到达时继续追加；若下游必须一次性接收“完整事件”，就需要等待下一头行或采用可修订的超时策略，无法同时保证立即完整和绝不发生晚到续行。

## 6. 轮转、重启和时效性边界

- **跨天/新文件**：先读完旧文件当前剩余数据，再切换新文件；区分新文件回填与新发生日志，不能重复报警或重复触发业务。
- **文件截断**：长度小于自己的 offset 时识别为新一代内容，重置解析状态和偏移。
- **同路径替换**：仅比较路径/长度不够；可用 Windows 文件身份识别新旧句柄，重开后记新 generation。新文件可能比旧 offset 更长。
- **短时异常**：目录不存在、共享冲突、访问失败时进入等待/重试并显示状态；不要崩溃，也不要显示成“已连接但日志为零”。
- **BGI 退出/重启**：存在旧日志文件不代表 BGI 仍运行；需要运行状态时另外只读检查目标进程。不要仅根据最后一条日志时间推断进程死活，空闲 BGI 可能没有新日志。
- **多实例**：同一文件可包含多个实例标识；按 instance/PID 筛选。多个文件时不能把“最新文件”视为已覆盖全部实例。
- **去重**：可用 `(文件身份/代次, 事件头字节偏移)` 作为事件键，续行更新同一事件。不要按消息文本去重，重复的相同日志可能是真实事件。
- **进度语义**：文件日志是观察数据；不要把一条成功文本当作任务完整终态凭证。本工具的目标只有日志读取与显示。
- **文件本身未写出内容**：级别过滤、文件写入失败、文件大小限制等可导致目标日志不在文件中。新工具不能恢复 BGI 从未写出的内容，不能声称读取进程内全部事件。

## 7. 与助手同时运行的结论

在当前源码中：

1. BGI 文件输出启用 `shared: true`。
2. 助手只读打开并共享 Read/Write/Delete。
3. 新工具按同样约定只读打开，保存自己的偏移，不获取助手单例锁或加入房间。

因此，**这条读取链不存在助手与新工具抢占日志、先读者消费掉数据、第二个读取者挤掉第一个的问题**。停止新工具只释放自己的流与 watcher，不应影响 BGI 或助手。

不把这个结论扩大为任意独占打开程序都兼容，也不把“能共同读文件”写成所有磁盘/权限/高负载条件下都有确定延迟。需要较高权限读取目标目录或进程路径时，应明确报告实际访问错误，而不是修改 BGI 文件权限。

## 8. 新会话直接执行的开发任务

> 实现一个独立于茶包 BGI 和 MultiplayerHoeingAssistant 的 Windows 小工具，只做 BGI 实时日志读取。不要修改 BGI 或助手，不依赖它们的源码工程/运行进程（BGI 本身除外），不使用房间服务或助手网页接口。
>
> 以本文为当前实现约定：用户选定 BGI exe/日志目录，UTF-8 字节增量读取，FileAccess.Read + FileShare.ReadWrite | FileShare.Delete；文件监听唤醒加 100～250ms 兜底；完整行及时显示，多行正文持续更新当前事件；有限历史单独标识；处理轮转、截断、同路径替换、重试和停止。所有配置与缓存归新工具自身。支持与助手同时只读访问。
>
> 不直接复制整个助手；可参考 BgiLogTailService 和 LogEntry 的相关逻辑，但它们只是源码参考，运行时不能依赖助手。助手现有约 2 秒尾事件收尾与 WebView 实例正则限制，不作为新工具必须继承的行为。
>
> 实现后用隔离日志夹具验证中文跨块、多行/空行、慢速续行、EOF 续读、无新日志、回填不冒充实时、滚动/截断/替换、停止释放句柄，以及两个独立读取者同时跟随同一持续写入文件。验证应直接服务这些约定，不能拿静态读文件测试替代持续追加与共享读取验证。
>
> 时效性同时测“日志写出到工具读到”“工具读到到显示”，报告观测分布或范围，并记录测试负载；不要把轮询间隔当作实测延迟。有条件时在不操作游戏任务、不改真实配置的前提下，对照正在运行的 BGI 与助手看同一实例的新日志，单独说明哪些是夹具验证、哪些是真实 BGI 验证。未执行的实机项如实标明。
