# 验证陷阱清单（做验收/测量前先读）

> 日期：2026-11-23
> 作者：verifier（dsh-team `team_mws24h8h198lvov`）
> 用途：这些都是**我自己在 SoulLink 验收过程中真实踩过的**坑。
> 每条都写清「症状 → 为什么骗人 → 正确做法」，避免下一个人重复浪费时间和下错结论。

---

## 0. 为什么需要这份清单

验收最危险的失败模式不是"测出问题"，而是**"测出错误的结论"**：

- 把正确实现判成错的 → 无谓返工
- 把错误实现判成对的 → 问题流到用户那里

下面每一条都曾经**让我得出过错误结论**，有几条甚至让我写进了文档才发现。

---

## 1. 注释里的关键词不是代码（静态检查类）

**症状**：grep `toDataURL` 命中，判定"网页还在做 JPEG 重编码"。

**真相**：命中的是这行**说明性注释**：
```javascript
// 旧版每帧 canvas.toDataURL('image/jpeg') 等于把省下的带宽又花回去
```
出现在 `Services/WebPages.cs:919` 和 `docs/web-index.html:903`。
它们是在描述"我们**曾经**这样做、现已移除"，不是调用。

**为什么骗人**：项目好的注释习惯就是解释历史决策，于是被移除的代码名会**长期留在注释里**。

**正确做法**：静态检查必须**排除注释行**：
```powershell
$raw | Where-Object {
    $t = $_.Line.Trim()
    -not ($t.StartsWith('//') -or $t.StartsWith('*') -or $t.StartsWith('/*') -or $t.StartsWith('<!--'))
}
```

## 2. 一个后端的失败 ≠ 进程级问题（必须做对照）

**症状**：agent 抓屏全黑，判定"进程级 DPI 上下文有问题"。

**真相**：只有 **WGC** 后端黑，**BitBlt** 后端完全正常。
两个后端共用同一进程、同一 DPI 上下文、同一会话 —— 所以不可能是进程级问题。

**为什么骗人**：只测一个实现路径，看到失败就归因到"进程/环境"，
听起来很有解释力（尤其配上 DPI 缩放这种"听起来就很容易出错"的因素），
但只要做个后端对照就能证伪。

**正确做法**：
- 至少找一条**已知能工作**的路径做基准（我用本进程 `Graphics.CopyFromScreen` 当基准）。
- 把可疑变量的**每一条实现路径**都跑一遍。
- 只有**所有**路径都失败，才能归因到进程/环境级。

> 这条坑我付出了代价：错误结论写进了 `STREAM-VERIFY` 初版，两小时后自己推翻。

## 3. 自己的测试工具可能没把参数传下去（元级陷阱）

**症状**：设 `SOULLINK_CAPTURE_MODE=0` 想测 BitBlt，结果 `recordstatus` 仍报 `capture=WGC`。
当时的解读：「环境变量不生效，是产品 bug」。

**真相**：我的 `ProbeHost` 里硬编码了 `psi.Environment["SOULLINK_CAPTURE_MODE"] = "1";`
—— 覆盖了外部设置的值。**是我的工具没传，不是产品不认。**

**为什么骗人**：工具是自己写的，天然倾向信任它；而且"环境变量不生效"听起来像个合理的产品缺陷。

**正确做法**：
- 用工具测产品之前，**先用工具测工具**（能传 `0` 就真的跑成 `0` 吗？）。
- 关键参数要在输出里**回显实测值**（我后来改成打印 `实测后端=BitBlt 尺寸=2560x1440（请求 mode=0）`）。
- 这条差点让我把整个黑屏归因搞错。

## 4. JSON 里的中文是 `\uXXXX` 转义（解析类）

**症状**：`Directory.Exists(返回的录像目录)` 恒为 `false`，判定"录像没生成"。

**真相**：协议返回的路径是：
```
C:\...\capture\\u5F55\\u5236\\u56DE\\u653E\\verify\\2026-11-23-020146-test
```
`\u5F55\u5236\u56DE\u653E` = **"录制回放"**。不解转义的话，这个路径当然不存在。

**为什么骗人**：前半段（`C:\...\capture\`）是 ASCII、看起来完全正常，
只有中文目录名部分被转义，很容易只看开头就以为是合法路径。

**正确做法**：解析协议字符串后**必须**做 Unicode 反转义再用于文件系统操作。

## 5. 同目录下的文件不一定都是"残留"（判据类）

**症状**：录像目录里发现 `shot.jpg`，判定"零 JPEG 没做到，还有 JPG 残留"。

**真相**：`shot.jpg` 是**静态截图**——用户明确要的功能，且是一次性的、不在实时通路上。
只有 `frame-*.jpg`（录像的中间序列）才算残留。

**为什么骗人**："目录里出现 .jpg" 是最直观的信号，但**功能归属**才知道它该不该在。

**正确做法**：判据要按**文件名模式 + 功能归属**区分，不能按扩展名一刀切：
- `frame-*.jpg` → 录像中间产物，**残留 = 不通过**
- `shot.jpg` → 静态截图，**允许保留**
- `replay.mp4` → 录像成品

**顺带的反向风险**：「零 JPEG」改造最容易**改过头**——把截图功能也一起删了。
所以检查脚本里要专门有一组"守护项"，验证截图和录像**仍然可用**。

## 6. 短采样窗口会骗人（测量类）

**症状**：采样 60 秒，内存涨到 973 MB 后"平了"，判定"泄漏已修复"。

**真相**：之后的进程涨到了 **1377 MB**（Lead 观察），我另一次采样 32 秒就冲到 1824 MB。
所谓"平了"，是恰好截在了 **GC 回收点**或**启动爬坡后的平台期**。

**为什么骗人**：内存曲线不是单调的，有锯齿。任意两点的首尾差都可能接近 0。

**正确做法**：
- 不要用「首尾差」判定，用**后半段线性回归 + R²**。
- 真泄漏的特征是 **斜率大 + R² 高（稳定单调）**；锯齿的特征是斜率存在但 **R² 很低**。
- 采样时长：**陡峭泄漏 ≥60 秒**能定性；**低速泄漏/句柄增长要 ≥15 分钟**
  （AGENTS.md：句柄增长要观察 >15 分钟才能定性，内存同理）。

## 7. 计时/缓冲/播放器会污染端到端数字

**症状**：端到端测出 636~742 ms，结论"我们链路慢"。

**真相**：其中约 **500 ms 是 ffplay 自己的缓冲**，我们链路只占 12~20 ms。
换到浏览器（WebCodecs）后这个数字完全不同。

**为什么骗人**：播放端在你测的链路"下游"，但它的缓冲会被计入端到端时间。

**正确做法**：
- 明确测量边界：是「服务端产帧 → 字节到达客户端」，还是「用户看到画面」？
- 播放端用不同实现（ffplay / 浏览器 / VLC）会得到完全不同的端到端数字，
  **不能混着比**。
- 分段测量优于端到端测量。

## 8. 构建产物可能取错目录（环境类）

**症状**：修了代码、重新构建，但测出来行为和旧版一致，怀疑"修改没生效"。

**真相**：产物在 `bin\Release\net11.0-windows10.0.26100.0\`（不带 `win-x64`），
而 `...\win-x64\` 子目录里躺着一份**旧时间戳的 DLL**。
按 `win-x64` 路径暂存 agent，跑的就是旧代码。

**正确做法**：
- 暂存前**回显产物时间戳**并与源码 mtime 比对（源码 01:39 → 产物应 ≥ 01:39）。
- 记住这里有两个 TFM 目录 + 一个 `win-x64` 子目录，容易拿错。

**相关**：暂存目录必须带**原名**的 `SoulLink.runtimeconfig.json` 和 `SoulLink.deps.json`。
把它们改名成 `SoulLink.Agent.*` 会让进程报 `hostpolicy.dll not found` 直接起不来。

## 9. 运行时长上限会伪装成"功能消失"

**症状**：`/stream` 跑 30 秒就断，怀疑"连接不稳定"。

**真相**：`AgentWebServer.cs` 里有 `frames < 450 && elapsedMilliseconds < 30000` ——
是**演示用的硬上限**，到期主动结束，不是故障。

**正确做法**：看到"固定时长后必然断开"，先去代码里找时长常量。

## 10. 快速自查表

做验收前问自己：

- [ ] 我的 grep/正则**排除注释**了吗？
- [ ] 我有一个**已知能工作**的基准做对照吗？
- [ ] 关键参数在工具里**真的传下去**并有回显吗？
- [ ] 从协议/JSON 拿到的字符串**解转义**了吗？
- [ ] 我的判据是按**功能归属**分类，还是按扩展名一刀切？
- [ ] 采样时长够定性吗？用的是斜率还是首尾差？
- [ ] 我测的是哪一段边界？播放端缓冲算进去了吗？
- [ ] 我暂存的产物**时间戳**比源码新吗？
- [ ] "固定时长后失效"是上限常量还是真故障？
