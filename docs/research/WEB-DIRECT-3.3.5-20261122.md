# 网页直连代理（3.3.5）

> 日期：2026-11-22
> 用户要求：「网页端尽量隔离主客户端」「模拟按键也有独立出来」
> 决策：「按 RDP 配置的用户来分配端口」

---

## 0. 一句话

网页的画面、录像回放、模拟按键**全部直连代理进程**，主程序只返回一张
「账号 → 端口」映射表，之后一个字节都不参与。

---

## 1. 改造前 vs 改造后

### 改造前（全部压在主程序）

```
浏览器 ──HTTP──> 主程序 ──管道──> 代理（截帧）
                    │              │
                    │        代理写盘 latest.jpg
                    │              │
                    └──轮询等文件变化（最多 600ms）──> 读回 ──> 浏览器
```

录像更直接：主程序开 `FileStream`，64 KB 缓冲一字节一字节搬给 socket。
**拖动进度条时浏览器连发 Range 请求，每个都要主程序搬。**

### 改造后（主程序只出数据）

```
浏览器 ──HTTP──> 主程序  /api/sessions   只返回「账号 → 端口」映射表
   │
   ├──HTTP──> 代理 :10801  /live        直取内存缓冲（实时画面）
   │                :10801  /api/input  本会话内注入键鼠
   │
   └──HTTP──> 主程序  /file/*.mp4        历史录像：主程序直接读硬盘
```

### ★ 历史回放**不**走代理（重要）

历史录像文件在 `<程序目录>\capture\录制回放\...\replay.mp4`，
那是主程序目录下的普通磁盘文件，主程序直接读即可。

代理跟这个目录只有「写」的关系（录制时存进去），没有读的职责；
让代理去服务这些文件是**纯多余的一跳**（同一台机器、同一块硬盘），
只会给一个提权进程增加攻击面。

判断依据：**数据是不是只有代理能拿到？**

| 数据 | 在哪 | 谁服务 |
|---|---|---|
| 实时帧 | 只有代理内存里 | 代理 `/live` |
| 键盘/鼠标注入 | 必须在该会话执行 | 代理 `/api/input` |
| 历史 MP4 / 截图 | 磁盘文件 | **主程序** `/file/` |

## 2. 端口分配规则

`Services/WebDirect.cs`：

```
端口 = WebPort + 账号在 App.Config.Accounts 里的序号 + 1
```

| WebPort | 账号序号 | 实际端口 |
|---|---|---|
| 10800 | 0（第一个账号） | 10801 |
| 10800 | 1 | 10802 |
| 10800 | 4 | 10805 |

**为什么按账号而不是会话号**：会话号会变（注销重登就换，实测 A2 从 17 变过），
按它分配会导致网页刷新后端口乱跳。账号 Id 是配置里的稳定主键。

**为什么是一账号一端口，不做汇聚**：见 §3 的实测。

## 3. ⚠ 实测结论：Windows 端口是独占的

这是本次最重要的验证。两个进程绑同一端口时：

```
job1 (先绑)  → served=12
job2 (后绑)  → served=0     ← 绑定"成功"了，但一个连接都收不到
```

客户端 12 次请求**全部**被第一个进程接走。这是最危险的失败模式：
**启动日志看不出异常，表现为"画面时有时无"或"永远连到别人"**。

验证方式（反证端口确实独占）：

```
PLAIN BIND FAILED: 通常每个套接字地址(协议/网络地址/端口)只允许使用一次
```

所以架构上放弃「多代理共享一个端口」，改成**一账号一端口**。
好处不止是能跑：某个账号的代理挂掉只影响它自己，是真正的故障隔离。

## 4. 代理怎么拿到配置

代理运行在 `C:\Program Files\SoulLinkDev\`，那里的 `data\` 与主控台的
`data\` **是两份**（`AppIdentity.DataDir` 按 exe 同目录规则各自算）。
所以代理读不到主程序的 `config.json`。

**全部走环境变量投送**（`RelayClient.CaptureEnv`）：

| 变量 | 用途 |
|---|---|
| `SOULLINK_CAPTURE_DIR` | 录像/截图根目录 —— **必须在主程序目录下，不写 C 盘** |
| `SOULLINK_WEB_PORT` | 直连端口（0/缺失 = 不启用） |
| `SOULLINK_WEB_TOKEN` | 共享口令（= `WebPassword`，空表示不校验） |
| `SOULLINK_ACCOUNT_ID` | 所属账号（`/api/info` 回显） |

★ **口令走环境变量而不是命令行**：命令行会出现在任务管理器/进程列表里，
等于把口令公开。

## 5. 安全边界

代理是**提权进程**，它开的端口等于提权面，必须严格：

1. **路径白名单**（`WebDirect.IsAllowedPath`）：只放行
   `/live`、`/api/input`、`/api/info` **三个**。代理不是通用文件服务器。
2. **口令校验**：`X-SoulLink-Token` 请求头。

★ 代理**不服务任何磁盘文件**。早先加过 `/file/`，后来删掉了：
  它服务的文件和主程序读的是同一块硬盘，纯多余的一跳。
  删掉它等于直接消掉一整类攻击面（目录穿越、Range 解析、编码绕过）——
  **不需要防护的最好办法是不要那个功能**。

实测（真实代理进程，18400 端口）：

| 请求 | 结果 |
|---|---|
| 无 token 访问 `/api/info` | 401 |
| 带 token 访问 `/api/info` | 200 |
| 访问 `/api/sessions`（主程序专属） | 404 |
| 访问 `/file/录制回放/.../replay.mp4` | **404（端点已删除）** |

## 6. 防火墙

方法：**一次性放行一个端口范围** `[WebPort+1, WebPort+16]`，
而不是每个账号一条规则（账号数会变，规则不该跟着变）。

- 规则名固定 `SoulLink Web Direct`，关掉网页访问时自动删除（不留垃圾）。
- 检测到三个防火墙配置档全关时直接跳过（本机就是这种情况）。

## 7. 前端

`docs/web-index.html` 里：

```js
function directBase(sess) {
  const p = sess && sess.directPort;
  if (!p || p <= 0) return '';
  return location.protocol + '//' + location.hostname + ':' + p;
}
```

- 主机名沿用当前页面访问用的那个（手机连 `192.168.x.x` 不会变成 `localhost`）。
- `directPort` 为 0 时自动回落主程序转发（保留旧路径，便于回退）。

★ **改了 web-index.html 必须跑 `scripts/sync-webpages.ps1`** ——
`Services/WebPages.cs` 是生成物，手抄会忘记同步（本项目踩过两次）。

## 9. 配置开关

`AppSettings.WebDirectToAgent`（默认 `true`）：

- `true` = 直连（本节所述）
- `false` = 全部经主程序转发（旧行为，保留以便回退）
