# 会话瘦身说明页：两区块设计 + 每个优化项的大白话说明

> 日期：2026-11-22
> 作者：dashboard（dsh-team）
> 前置：`SESSION-SLIM-DEEP-20261122.md`（perfmeasure，实现侧 v2.0，**两层拆分 + 数字口径以它为准**）、`Services/SessionSlimmer.cs`（564 行，当前实现）
> 范围：只读分析 + 设计判断。**未改业务代码、未动 dist/、未提交 git**。
> 用户诉求：① 分账号 / 全机两层，能分账号的按账号、不能分账号的独立出来让用户选；② 每个优化项都要讲清"这是什么、关掉会失去什么"，不能只列进程名和数字；③ 界面留白充足，区块 B（全机）必须警告色 + 默认关闭 + 一键恢复。

## 0. 一句话结论

1. **页面拆成两个视觉区块 + 一个"必须保留"说明区 + 底部操作条**：区块 A「按账号隔离」默认开启、正常色系；区块 B「全机设置」默认关闭、警告色、一键恢复。三者之间用 **30px+ 间距 + 独立卡片边框** 硬隔离，绝不把开关混进同一个列表。

2. **每个优化项一律用四行格式**：`这是什么 / 关掉后 / 还保留 / 占内存`。**只写进程名和数字 = 没告知**，用户看不懂 SearchHost 是什么，但看得懂"任务栏搜索：按 Win 键打字找程序的对话框"。

3. **三个独立开关**，与实现侧的字段一一对应：
   - `SessionSlimKillEnabled`（分账号杀进程，默认 `true`）→ 区块 A 第 1 项
   - `SessionSlimUserPolicyEnabled`（分账号用户设置，默认 `true`）→ 区块 A 第 2 项
   - `SessionSlimMachinePolicyEnabled`（机器级，默认 `false`）→ 区块 B

4. **两处技术要点已按 perfmeasure 为准落定**（他做实现侧）：
   - SearchHost / Widgets 的关闭策略是 `class=Machine`，**只能写 HKLM、只能全机生效** → 归入区块 B（全机），不能塞进"按账号"。
   - `msedgewebview2` **不是独立项**，是 SearchHost 和 Widgets 拉起的 Edge 内核子进程 → 不单独列开关，随上面两个一起消失。

**布局硬约束**：
- 区块 A 与区块 B 之间间距 **≥ 30px**，且各自是独立圆角卡片（不是同一列表里的两段）。

- 底部操作条固定，只有「关闭」一个主动作。

## 2. 每个优化项的四行说明（大白话，默认折叠，关键项展开）

> 格式固定：`这是什么 / 关掉后 / 还保留 / 占内存`。**默认折叠**（避免一屏全是字），但 SearchHost、Widgets、explorer 三项**默认展开**。
> "占内存"数字为说明性估算；页面上的"预计节省"应**实时计算**（`SessionSlimmer.Count()` 的 `KillableBytes`/`PolicyOnlyBytes`），不写死。

### 2.1 区块 A：按账号隔离（能分账号，默认开启，mint/accent 色）

#### ① 浏览器本体（msedge / Edge）

- 这是什么：你在挂机账号里开过的 Edge 浏览器窗口，就是它。
- 关掉后：只是关掉浏览器窗口，不影响游戏。
- 还保留：游戏、脚本、其他程序全部正常。
- 占内存：约 391 MB（如果开过的话——本机 A2 会话当前没开，此时收益为 0）。

#### ② 手机连接（PhoneExperienceHost）

- 这是什么：Windows 的"手机连接"功能，能把手机的通知、照片同步到电脑上。
- 关掉后：手机上收到短信/照片不会弹到电脑上。挂机用不到。
- 还保留：手机和游戏本身都不受影响。
- 占内存：约 98 MB。

#### ③ 跨设备服务（CrossDeviceService / CrossDeviceResume）

- 这是什么：跨设备协同——比如手机上复制文字、电脑上能粘贴；手机上开始的事，电脑上接着做。
- 关掉后：这些"跨设备接力"功能没了。挂机用不到。
- 还保留：本机正常的复制粘贴、程序使用都不受影响。
- 占内存：约 123 MB（74 + 49）。

#### ④ 游戏栏（GameBar / GameBarFTServer / GameBarPresenceWriter）

- 这是什么：按 Win+G 调出来的那个 Xbox 游戏覆盖层（录屏、截图、性能面板）。
- 关掉后：Win+G 没反应，游戏内录屏/截图用不了。挂机用不到。
- 还保留：游戏本体正常，不受影响。
- 占内存：约几十 MB。

#### ⑤ 触摸键盘（TabTip）

- 这是什么：平板模式下自动弹出的那个屏幕键盘。
- 关掉后：触摸键盘弹不出来。挂机（用键鼠操作）用不到。
- 还保留：物理键盘输入完全正常。
- 占内存：约 64 MB。

#### ⑥ 首次登录向导（UserOOBEBroker）

- 这是什么：Win11 第一次登录时那个"欢迎/设置向导"。登录一次之后就没用了。
- 关掉后：没有任何影响。
- 还保留：全部正常。
- 占内存：约 11 MB。

#### ⑦ OneDrive 授权（FileCoAuth）

- 这是什么：OneDrive 的文件协作授权进程。如果你不用 OneDrive，它纯属浪费。
- 关掉后：OneDrive 同步可能受影响（不用就无影响）。
- 还保留：本地文件、游戏都不受影响。
- 占内存：约 21 MB。

#### ⑧ Edge 预启动 / 后台模式（区块 A 第 2 个开关）

- 这是什么：Edge 会在后台偷偷自启（预启动），让浏览器"秒开"，代价是常驻内存。
- 关掉后：浏览器首次打开会慢一点点，但不再后台常驻。
- 还保留：浏览器正常使用完全不受影响。
- 占内存：取决于是否常驻（本机 msedge 不在跑时收益 0）。

### 2.2 区块 B：全机设置（机器级，默认关闭，amber 警告色）

> ★ 前置说明（必须写清，用户才能理解为什么"分不开"）：这两个组件是 Windows 系统服务拉起来的，**不是某个账号独有的东西**，所以只能做成"整台机器一起关"，不能只对挂机账号关。

#### ① 任务栏搜索（SearchHost）

- 这是什么：就是任务栏那个搜索框。你按 Win 键开始打字找程序、找文件、找设置，弹出来的界面就是它。它内部用了 Edge 浏览器内核（所以还带了一堆 msedgewebview2 子进程）。
- 关掉后：任务栏搜索框点了没反应；Win+S 快捷键失效；开始菜单打字搜索也用不了（⚠ 见 §5 与 perfmeasure 的口径差异，需 Lead 确认）。
- 还保留：开始菜单本身正常（能点开始、能看程序列表、能右键）；文件资源管理器正常；游戏完全不受影响。
- 占内存：约 300 MB/会话（进程本身 110 MB + 它拉起的浏览器内核子进程约 190 MB）。

#### ② 小组件面板（Widgets）

- 这是什么：任务栏左下角那个天气/新闻面板，点进去是一堆资讯卡片，同样用 Edge 内核。
- 关掉后：那个面板没了，点不出来。
- 还保留：什么都不受影响——绝大多数人不用这个功能。
- 占内存：约 92 MB/会话（53 MB + 其浏览器内核子进程 39 MB）。

#### ③ 关于 msedgewebview2（不是独立开关，必须写清）

- 这是什么：那 13 个 msedgewebview2 进程**不是独立的软件**，是 SearchHost 和 Widgets 拉起来的 Edge 浏览器内核。
- 关掉后：关掉上面两个（搜索 + 小组件），它们自然一起消失。
- **绝不单独列成一项让用户勾选**——它是"果"不是"因"。

### 2.3 不影响什么（保留项，明确"不提供关闭选项"）

| 项 | 这是什么 | 为什么必须保留 |
|---|---|---|
| **explorer**（桌面 + 文件资源管理器） | 桌面、任务栏、文件管理器窗口都是它 | 关掉只剩空桌面：双击程序、开文件夹、任务栏全没了。**不提供关闭选项**。约 170 MB（必须付） |
| **StartMenuExperienceHost**（开始菜单） | 点左下角开始按钮弹出的那个菜单 | 关掉开始菜单就没反应了。**不提供关闭选项**。约 123 MB（必须付） |
| **TextInputHost**（输入法候选框） | 打字时弹出候选词的小窗口（微软输入法） | 关掉可能打不了中文、候选框出不来。**建议保留**——你随时可能连进去聊天、输文字。约 84 MB |
| **ShellHost**（shell 组件宿主） | 文件操作对话框（"打开文件""另存为"）、拖放、快捷键的底层宿主 | 关掉可能打不开文件选择框、拖拽失效；且只占 0.01% CPU，性价比最差。**建议保留**。约 54 MB |

## 3. 视觉规范（纯 CSS 变量，两套主题通用，不引框架）

复用现有 `--mint/--amber/--rose/--accent` 语义（与 DASHBOARD-DESIGN §2.6 一致）：

| 区块 | 配色 | 默认开关态 | 强调方式 |
|---|---|---|---|
| 标题区 | 中性（`--txt`/`--txt3`） | — | 标题 18px 加粗，副标题 12.5px 次级 |
| **区块 A** | `--mint`（正常绿） | **开** | 1px `--border` 边框 + mint 左缘状态条 |
| **区块 B** | `--amber`（警告黄） | **关** | **2px amber 边框 + `--amber-bg` 背景 + 顶部 ⚠ 图标**，比区块 A 显眼得多 |
| 不影响什么 | 中性 | 无开关 | 1px `--border`，纯说明 |
| 底部操作条 | `--card2` | — | 右对齐「关闭」主按钮 |

**层级**：标题 18px 加粗 → 区块标题 15px 加粗 → 项名称 13.5px → 四行说明 12px（`这是什么` 用 `--txt`，`关掉后` 用 `--rose`，`还保留` 用 `--mint`，`占内存` 用 `--txt3`）。

**折叠规则**：每个优化项是一个可折叠块（点标题展开四行说明）。SearchHost、Widgets、explorer 三项**默认展开**，其余默认折叠。折叠块之间 8px 间距。

## 4. 配置字段映射（与实现侧对齐）

| 配置字段 | 归属区块 | 默认值 | 对应 UI |
|---|---|---|---|
| `SessionSlimKillEnabled` | 区块 A | `true` | 开关「清理会话外围进程」 |
| `SessionSlimUserPolicyEnabled` | 区块 A | `true` | 开关「关闭 Edge 预启动/后台」 |
| `SessionSlimMachinePolicyEnabled` | 区块 B | `false` | 开关「关闭任务栏搜索 + 小组件」 |

> 区块 B 的「恢复默认设置」按钮 = 撤销机器级策略（删掉写过的 HKLM 值）+ 把 `SessionSlimMachinePolicyEnabled` 置回 `false`，并给用户一条"已恢复系统默认"的回执。**只作用于区块 B**，不碰区块 A 的开关。

## 5. 给 Lead 的确认项（两处口径差异）

1. **"开始菜单打字搜索"是否受影响**：
   - perfmeasure（实现侧）说：`DisableSearch=1` 关的是任务栏搜索面板（SearchHost），**开始菜单里直接打字搜索仍可用**（那是 StartMenuExperienceHost，保留）。
   - 用户（parent 转述）说：开始菜单打字搜索**也用不了**。
   - **建议**：按 perfmeasure 为准（他做过模块级实测），最终文案把"开始菜单打字搜索"从"关掉后"挪进"还保留"；若用户坚持"也关掉"，需要额外确认。**请 Lead 拍板后我改文案。**

2. **占内存数字**：本设计的"占内存"是说明性估算（parent 已核对本机进程）。但 perfmeasure v2.0 的实测表更精确（如 SearchHost+WebView2 = 409 MB 而非 300 MB）。**页面上的"预计节省"应实时算，不写死静态数字**；若要在折叠文案里展示静态数字，以 perfmeasure 的 v2.0 实测表为准。
