## 1. 用户反馈（三个问题）

> 「蓝色原点没有跟随，也没自动填入，而且这个地方太小，

## 2. 问题一：蓝色标记不跟随

### 原因

`pickMark` 是一个 `Ellipse`，靠 `Margin` 定位，塞在 `Grid` 里：

```csharp
var previewImg = new Image { Stretch = Stretch.Uniform, MaxHeight = 240, HorizontalAlignment = Left };
...
previewImg.Source = bmp;
// 没有把比例换算成 Margin ← 关键
```

两个致命点：

1. **从来没算过 Margin**：`RenderPick` 只把 `pickMark.Visibility` 设成 Visible，
   位置一直停在默认的 (0,0) 附近；
2. 即使算了，也是错的：`Stretch=Uniform` + `Left` 对齐时，
   **图片实际绘制区域 ≠ Image 元素区域**（上下或左右会有留白），
   按元素尺寸算出的偏移必然对不上。

### 修复

按 Uniform 的真实几何反推：

```csharp
double scale = Math.Min(boxW / srcW, boxH / srcH);
double drawW = srcW * scale, drawH = srcH * scale;
double offX = (boxW - drawW) / 2.0, offY = (boxH - drawH) / 2.0;
thumbMark.Margin = new Thickness(nx * drawW + offX - 6, ny * drawH + offY - 6, 0, 0);
```

另外 `ActualWidth` 只有在布局完成后才有值，所以用
`Dispatcher.BeginInvoke(..., DispatcherPriority.Loaded)` 排队重画一次，
并挂 `SizeChanged` 兜住窗口缩放。

## 3. 问题二：坐标没有自动填入

### 原因

1. 点击取的是 `ev.GetPosition(previewImg)`，**点在图片外的留白区就 `return`** 了，
   用户点了但什么都没发生；
2. 更关键：写完 `node.Set("x"/"y")` 后，**没有刷新属性面板里的 X/Y 输入框** ——
   那两个 TextBox 只在面板重建时才读节点值，所以界面上一直显示旧数字。

### 修复

* 点选改为在大窗口里做（见问题三），坐标按 canvas 内图片的**实际绘制矩形**换算，
  黑边区域直接判定无效并给出可视化反馈（不在黑边上乱点）；
* 新增 `SyncXYBoxes()`：点选后遍历 `_propUi`，找到 `Tag == "x"/"y"` 的 TextBox 刷新文本；
* 为此给默认文本框分支补了 `Tag = p.Key`（之前没打标签，找不到对应输入框）。

## 4. 问题三：预览太小 → 改成弹大窗点选

右侧属性面板只有 220px 宽，`MaxHeight=240` 缩略图根本瞄不准。

### 现在的交互

```
[选择截图…] [清除选点]
┌─────────────────┐
│  缩略图（含蓝点） │ ← 点它打开大窗口
└─────────────────┘
将点击 (960, 540) ［按 1920×1080 换算］
```

点缩略图 → 弹出大窗口（屏幕 85% 以内、保持图片比例、小图不放大）：

* 图片按 `Uniform` 居中，**实时跟随鼠标**显示十字圆环 + 当前坐标；
* **单击即确认 → 写回比例 + 刷新缩略图标记 + 刷新 X/Y + 自动关闭**；
* Esc 或「取消」按钮放弃（这里 Esc 是取消——它不在录按键，不冲突）；
* 黑边区域点击无效（不会把坐标算到图片外）。

## 5. 验证（无 UI，真实 WPF 布局计算）

造了一张 1600×900 测试图，复刻大窗口的布局与换算逻辑：

```
canvas=885x583  img=885x498  offset=(0,42)      ← 16:9 图在 885x583 里居中
中心点击 → 比例(0.500,0.500) → 像素(800,450)     ← 正好是 1600x900 的中心 ✓
左上角   → 像素(2,2)
点在黑边内 → 判定无效 = True                     ← 留白区不会误算
RESULT: PASS — 居中显示 + 比例换算正确
```
