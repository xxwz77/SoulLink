# SoulLink 交接文档 · 2.17.33（通道门控：先建通道，再判定条件）

> 时间：2026-11-20 18:00
> 版本：**2.17.33.0**（待定版；可信归档仍是 2.17.19）
> 性质：修正执行时序 —— 条件判定必须发生在通道就绪**之后**
> 用户要求：**界面操作由用户自己测，助手不做界面测试**

---

## 1. 用户指出的问题

> 「运行条件没用跟随，运行条件应该在建立通道后进行判断。
>   现在是运行条件先判断，通道完成立刻执行」

## 2. 之前的错误时序

2.17.30 的实现是：**先 ScanAsync（判定条件 + 执行动作）**，
通道没就绪才在 `RunInputAsync` 里等待。后果：

1. 条件用的是**通道建立之前**的采样值；
2. 通道一就绪就立刻把"当时判定通过"的动作**补发**出去；
3. 对「定时·间隔」这类**脉冲型触点**尤其致命：
   间隔到点的脉冲在通道没好时就已经点亮并写进
   `SatisfiedContacts` / `ContactPulseAt`，通道建好后立刻补执行一次 ——
   而这次执行并不代表"现在条件满足"。

用户描述的正是这个现象：**条件先判定，通道完成立刻执行**。

## 3. 正确时序（2.17.33）

```
RunAsync
  ├─ 若本流程要用注入通道（UsesInjection）
  │    └─ EnsureChannelBeforeScanAsync  ← ★ 先确保通道就绪
  │         ├─ 未就绪 → 本轮**不判定条件、不执行动作**，只挂等待态（黄灯+提示）
  │         └─ 就绪   → 重新取 time = DateTime.Now   ← ★ 时间也刷新
  └─ ScanAsync（在通道就绪的**当前时刻**重新判定条件）
```

关键点：

* **时间必须重取**：`time = DateTime.Now` 在门控通过后重新赋值，
  否则判据还是"进函数那一刻"的时间，间隔触点可能立刻又满足一次；
* **不通过就不判定**：门控失败直接返回，连 `ScanAsync` 都不进，
  根本不存在"补发"的可能；
* **只对需要的流程门控**：`UsesInjection` 只看是否有
  模拟按键 / 鼠标移动 / 点击 / 滚轮 节点；
  纯本地动作（等待、启动进程、关 BGI、启动一条龙…）不受通道影响。

## 4. 一个必须堵死的漏洞：没有会话 ≠ 可以放行

第一版门控写的是：

```csharp
if (sid <= 0) { flow.WaitingChannel = ""; return (true, ""); }   // ← 放行了
```

探针立刻暴露问题：**A2 会话号取不到时门控直接放行**，条件照样判定、
动作照样执行 → 报"目标账号没有会话"，门控形同虚设。

改为：`sid <= 0` 说明**通道不可能就绪**，必须挡住，并给出可读原因：

```
WaitingChannel = "等待「A2」的会话上线 / 通道建立…"
msg            = "目标账号当前没有登录会话，本轮不判定条件（不会补发）"
```

（并用 `AccountStateCenter` 兜底取会话号，避免流程账号与会话号不同步时误挡。）
