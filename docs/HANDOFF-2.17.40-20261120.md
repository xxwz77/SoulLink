## 1. 用户反馈

> 「双列模式没有自适应窗口大小，应该是保持画面比例，适应窗口大小」

截图里两个画面只占上半部分，下半屏全空着。

## 2. 根因：只按宽度推高度，宽屏下必然只占一半

`Services/ViewLayout.cs` `ComputeTwoColumn`：

```csharp
int cellW = Math.Max(1, (vw - Gap * (cols + 1)) / cols);
int cellH = Math.Max(1, (int)Math.Round(cellW / Aspect));   // ← 唯一的高度来源

int maxCellH = Math.Max(1, (vh - Gap * 2) / 2);
if (cellH > maxCellH) { cellH = maxCellH; cellW = ... }      // ← 只缩不放
```

两条式子的问题：

1. `cellH` **只由宽度推导**（`cellW / 16:9`）；
2. `maxCellH` 分支只在"高度放不下"时**缩小**，从来不会**放大**。

于是宽屏（1500×500 这类）下，按宽度算出的高度只有视口的一半左右，
剩下空间白白浪费 —— 看起来就是"没有自适应"。

## 3. 实测数据（修复前）

```
视口 1500x500  → 格子 430x242  比例 1.78  高/视口 = 48%
视口 1500x700  → 格子 608x342  比例 1.78  高/视口 = 49%
视口 1900x1000 → 格子 875x492  比例 1.78  高/视口 = 49%
```

比例是对的（16:9），但**高度只用了一半**。

## 4. 修复

在保持 16:9 的前提下，让格子**在两个上限内尽量大**：

```csharp
int rowsTotal = Math.Max(1, (count + cols - 1) / cols);
int availW = Math.Max(1, (vw - Gap * (cols + 1)) / cols);
int availH = Math.Max(1, (vh - Gap * (rowsTotal + 1)) / rowsTotal);

int cellW = availW;                                    // 先按宽度铺满
int cellH = (int)Math.Round(cellW / Aspect);
if (cellH > availH) {                                  // 高度是瓶颈 → 按高度反推
    cellH = availH;
    cellW = (int)Math.Round(cellH * Aspect);
}
```

**关键点**：两种情况的最终宽高都**不会越界**。
我第一次改的时候漏了这个约束，导致两列横向溢出（右界 1736 > 视口 1500），
那是比"只占半屏"更糟的问题（画面会被裁掉）。探针检测到后立即修正。

## 6. 关于"高度只占一半"的几何解释（重要）

两列并排时，**宽度是唯一瓶颈**：

```
两个 16:9 格子并排 → 总宽 : 单格高 = (2 × 16) : 9 = 32 : 9 ≈ 3.56 : 1
```

所以在 1500×500（3:1）的视口里，两个格子铺满宽度后高度必然只占约 500 的 83%，
在 1500×700（2.14:1）的视口里只占 59% —— 这是**数学必然**，不是缺陷。

如果希望画面占满整个视口高度，正确做法是**切换布局模式**：
* 「网格」模式 → 等分铺满（但格子比例会变形）；
* 「单画面」模式 → 铺满（比例变形）。

双列/单列的语义是"保持 16:9、可滚动浏览"，本次修复保证的是：
**格子尺寸真的跟随窗口变化**（原来不跟随），而不是强行拉伸。
