# SoulLink 交接文档 · 2.17.30（执行前等待注入通道：黄灯 + 保持提示）

> 时间：2026-11-20 17:25
> 版本：**2.17.30.0**（待定版；可信归档仍是 2.17.19）
> 性质：输入类动作执行前先等注入通道就绪，等待期间黄灯 + 保持提示
> 用户要求：**界面操作由用户自己测，助手不做界面测试**

---

## 1. 用户要求

> 「执行要加个判断，需要等待通道建立，标黄灯，保持提示。等到通道真真建立。」

## 2. 原来的问题

`Services/FlowRunner.cs` 的 `RunInputAsync`：

```csharp
var relay = RelayClient.FindBySession(sid);
if (relay == null || !relay.IsConnected) return (false, "该会话没有已连接的注入通道（请先投送）");
```

**通道没就绪 = 立刻判失败**。但 RDP 刚连上时注入代理还在投送中
（投送 + 连管道通常 1~5 秒，Broker 模式还要等服务起进程），
这段时间查 `FindBySession` 必然拿到 null →
动作记为失败 → 灯变**红** → 用户以为坏了，实际只是还没连上。

## 3. 改动

### 3.1 引擎：等待而不是失败（`Services/FlowRunner.cs`）

```csharp
internal const int ChannelWaitMs = 20000;   // 最多等 20 秒

private static async Task<string?> WaitForChannelAsync(int sid, string actionTitle, AutomationFlow? flow)
{
    // 已就绪 → 直接返回 null
    // 否则每 250ms 轮询 FindBySession，一旦 IsConnected 立刻继续
    // 超时 → 返回具体原因（不再是无信息量的"没有通道"）
}
```

`RunInputAsync` 改为先等通道再执行。覆盖的动作：
**模拟按键 / 鼠标移动 / 鼠标点击 / 滚轮**（同一分支）。

等待期间：

* `flow.WaitingChannel = "等待注入通道建立（会话 N）…"` → 界面据此画黄灯；
* 触发 `FlowRunner.ReportChannelWait` 事件（其他订阅者可自行响应）；
* 写一条 `LogBus.Info("等待注入通道", …)`，就绪时再记 `"通道已就绪 · 等待 Nms"`。

超时文案：`等待注入通道超时（20 秒）：该会话仍未建立通道，请检查投送状态后重试`

### 3.2 界面：黄灯 + 提示优先级最高（`Views/LaunchPage.xaml.cs`）

灯色判定顺序（2.17.30 后）：

| 顺序 | 条件 | 颜色 |
|---|---|---|
| 1 | 暂停 / 未启用 | 黄 |
| 2 | **正在等注入通道** | **黄（等待）** |
| 3 | 今日已完成（END 锁存） | 橙 |
| 4 | 保鲜期内失败 | 红 |
| 5 | 保鲜期内成功 | 绿 |
| 6 | 其余 | 蓝 |

摘要里 `WaitingChannel` **优先级最高**（在暂停之前）—— 用户明确要求"保持提示"，
否则这条信息会被"执行成功 / 等待下一次"盖掉。

`WaitingChannel` 标了 `[JsonIgnore]`：它是瞬时运行态，不该写进配置。

## 4. 验证（无 UI，真实引擎）

直接反射调用私有 `RunActionAsync(act, "x", 4, cfg, flow)`，
传入**真实会话号 4（A2 所在会话）**，但让注册表里没有该通道 → 必然走等待分支：

```
起始灯 = 蓝(等待)
  t+0s   灯=蓝(等待)      等待：条件满足时自动执行
  t+1s   灯=黄(等待通道)  等待注入通道建立（会话 4）…      ← 保持提示
  t+2s   灯=黄(等待通道)  等待注入通道建立（会话 4）…
  ...（每 700ms 采样一次，持续 20 秒全程黄灯 + 同一提示）
结果：耗时 20190ms
  ok=False  msg=等待注入通道超时（20 秒）：该会话仍未建立通道，请检查投送状态后重试
  WaitingChannel 已清空=True
  最终灯 = 蓝(等待)
```

要点：
* 等待期间**全程黄灯**，不是红色失败；
* 提示文字**保持不消失**（用户要求）；
* 超时后自动清空等待态，回到蓝色等待，并给出可读原因。

> 第一次探针没触发等待：因为 `sid=0` 时 `RunInputAsync` 在更早的
> `if (sid <= 0) return (false, "目标账号没有会话");` 就返回了。
> 必须用**真实会话号**才能走到等待分支 —— 这条记下来，免得下次又白跑。
