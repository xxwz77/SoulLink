## 1. 用户反馈的三件事

1. 执行的时候没有亮绿灯。
2. 添加任务之后需要手动按一次开关才会自动执行。

## 2. 逐个结论

### 2.1 绿灯不亮 —— 是显示逻辑错了（已修）

`Views/LaunchPage.xaml.cs` `BuildAutomationCard` 原来这样定色：

```csharp
bool excluded = !AccountScope.Allows(OwnerUserNameOf(f));
bool anyLit = !excluded && f.RuntimeStates.Any(kv => kv.Value.Value && f.FindNode(kv.Key)?.IsContact == true);
Color dotColor = excluded ? 灰
    : paused ? 灰蓝 : f.IsDailyComplete ? 琥珀
    : anyLit ? 青绿 : 灰;
```

两个致命点：

* **「仅管理挂机账号」开着时（本机 `OnlyAutomationAccounts=True`），流程账号是主用户 lummy
  → `excluded=true` → 无条件灰色**。无论跑没跑都是灰的。
* 即使不 excluded，`RuntimeStates` 里触点"为真"的窗口极短：
  `TrigInterval` 的脉冲只在 `ContactPulseAt` 记录的 2 秒内为真，
  而界面 **3 秒**才刷一次，采样几乎必然落在"假"的那一帧。

**实测佐证**：本机 3 个流程 `RunCount` 已累计到 **415 / 263**，说明它们一直在跑，
但灯是灰的 → 灯根本不是在反映"有没有执行"。

**修复**：灯改为反映「此刻是否处于自动执行状态」：

| 状态 | 颜色 |
|---|---|
| 暂停 / 未启用 | 灰蓝 |
| 有 END 且今日已完成 | 琥珀 |
| **只连了「手动」触点（绝不自动跑）** | **青色** |
| 启用且今天会跑 | 青绿 |
| 其余 | 深灰 |

并且 `「仅管理挂机账号」不再影响这盏灯` —— 它是**控制状态**，不是挂机目标的运行数据。

### 2.2 "添加任务后要手动按一次开关才会自动执行" —— 取决于用了哪种触点（已加提示）

无 UI 探针（真实 `FlowRunner.RunAsync`）实测：

```
A. 全新 TrigInterval 流程，连续 5 次自动扫描
  第1次: Triggered=True  Passed=False  触点灯=True
  → 新建的「定时·间隔」流程 **第一次扫描就会自己执行**，不需要先手点
```

所以"必须手点一次才自动执行"的真实原因是**新建流程默认连的是「手动」触点**：

`FlowNodeCatalog` 里 `TrigManual` 的定义就是
**「手动」— 仅点击「立即运行」时满足**（`FlowRunner` 里 `case TrigManual: return manual;`）。
这种流程**永远不会自己跑**，点「立即运行一次」才会执行 —— 这是设计如此，不是 bug。

真正的问题是**界面没说**：卡片摘要原来对主用户只显示「2 个条件 · 1 个动作」，
"要不要手点"完全看不出来。

**修复**：`AutomationFlow.TodayRunState()` 增加手动触点识别，摘要现在显示
`… · 需要手动触发：只连了「手动」触点，点「立即运行一次」才执行`，
灯也用青色区分开。

### 2.3 重启后是否保留 —— **会保留**（已实测）

机型重启实测（客户端 kill → 重新启动 → 等 40 秒，读 config）：

| 流程 | 重启前 RunCount | 重启后 RunCount |
|---|---|---|
| db9328b9（手动） | 11 | 11（本就不该自己跑） |
| 38212a3a（间隔） | 415 | **418** |
| 6c071938（间隔） | 263 | 263（间隔 3 秒，40 秒内可能恰好没跨周期） |

三个流程 `Enabled=True / Paused=False` 全部原样保留，
两个间隔流程重启后**继续自动执行**。`Enabled` / `Paused` 是持久化字段（`config.json`），
只有"今天要不要跑"的锁存按日界滚动。
