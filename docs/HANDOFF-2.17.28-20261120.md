# SoulLink 交接文档 · 2.17.27 / 2.17.28（状态灯要随执行交替，不能焊死在绿）

> 时间：2026-11-20 17:00
> 版本：**2.17.28.0**（待定版；可信归档仍是 2.17.19）
> 性质：修状态灯"绿了就再也不回蓝"
> 用户要求：**界面操作由用户自己测，助手不做界面测试**

---

## 1. 用户反馈

> 「自动化中，等变绿之后没变回蓝色，一直显示执行成功。应该根据状态交替才对」

## 2. 根因

2.17.23 把 `LastRunOk` 当成**持久状态**直接决定颜色：

```csharp
: f.LastRunOk == true ? 绿 : 蓝
```

执行成功一次，`LastRunOk` 就永远是 `true` → 灯永远绿，看不出"这轮跑完了、又回到等待"。

## 3. 修复思路：给结果加"保鲜期"

```csharp
bool resultFresh = f.LastActionResultAt.HasValue
    && (DateTime.Now - f.LastActionResultAt.Value).TotalMilliseconds <= LastResultHoldMs;
```

超出保鲜期 → 回蓝（等待）。灯于是随每轮执行**交替闪烁**。

### 3.1 踩了两次坑，记清楚（关键）

保鲜期取值有严格约束：**保鲜期 < 界面刷新周期 < 执行间隔**。

| 尝试 | 取值 | 结果 |
|---|---|---|
| 第一次 | 6000ms | 比执行间隔（2s/3s）还长 → 每轮扫描时上次结果仍"新鲜" → **永远绿** |
| 第二次 | 1500ms | 比执行间隔短了，但**仍大于界面 1 秒重建周期** → 每次重建都恰好在保鲜期内 → 实测**仍焊死**（12 秒采样全是绿） |
| 最终 | **700ms** | 界面每秒重建，必然出现"这次绿、下次蓝" → 实测交替 |

**教训**：判断"瞬时状态"的显示时，保鲜期必须是刷新周期的**真子集**，
否则采样永远落在"真"的区间里，看起来跟永久状态没区别。

### 3.2 配套：界面刷新从 3 秒降到 1 秒

原来自动化卡片跟随会话列表 **3 秒**刷新，保鲜期再短也可能整帧错过。
新增独立轻量定时器 `_automationTimer`（1 秒）：

* 只重建自动化卡片（元素很少，开销可忽略）；
* **不**查会话、**不**查进程（那些仍走 3 秒的 `_sessionTimer`）；
* `Loaded` 启动 / `Unloaded` 停止 / `Activate` 兜底重启，沿用本文件既有惯例。

### 3.3 摘要文案同步交替

| 时机 | 文案 |
|---|---|
| 保鲜期内，成功 | `执行成功「模拟按键」 · 16:37:00` |
| 保鲜期内，失败 | `执行失败「模拟按键」：原因 · 16:37:00` |
| 已过期 | `等待下一次 · 上次成功 16:37:00` |

  t+  3.1s  灯=蓝(等待)

各颜色采样次数：[红, 8]  [蓝, 8]
