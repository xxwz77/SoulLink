> 时间：2026-11-20 16:50

> 性质：按用户要求调整"开箱即自动执行"的默认行为，并把两个长得一样的按钮分开

## 1. 用户的两条要求

> 「新建跟重启就要自动跑，除非用户暂停或者删除」
> 「自动跑的按钮与手动触发区别不大，要做区分」

## 2. 原来的问题

### 2.1 两个按钮长得一模一样

`BuildAutomationCard` 里：

| 按钮 | 图标 | ToolTip |
|---|---|---|
| 自动开关 | `\uE768`（播放） | 恢复 / 暂停 |
| 手动触发 | `\uE768`（播放） | 立即运行一次 |

**同一个图标、同一尺寸**，只有悬浮提示不同 —— 用户实测分不清是可以预期的。

### 2.2 新建流程默认不能自己跑

编辑器对空流程不种任何节点，用户手动加的第一个触点常常是「手动」
（`TrigManual` 只在 `manual=true` 的扫描里为真）→ 新建后必须点一次才动。

## 3. 本次改动

### 3.1 新建流程：显式开启自动运行（`Views/LaunchPage.xaml.cs`）

```csharp
var flow = new AutomationFlow
{
    ...
    Enabled = true,   // ★ 显式写出，防止以后改默认值又把"新建即暂停"带回来
    Paused  = false
};
```

### 3.2 新建流程：默认种「定时·间隔 5 秒」触点（`Views/FlowEditorWindow.xaml.cs`）

只在 `_isNew && Nodes.Count == 0` 时执行，不连任何动作、不产生副作用。

**为什么不用「会话在线」**：它依赖 `AccountStateCenter` 的会话快照，
账号没登录时恒为 false，探针实测动作永远不执行（会让人以为"又不动了"）。
「定时·间隔」是纯本地计时，只要程序开着就一定会触发，是"新建就能自己跑"的可靠底座。

### 3.3 两种按钮彻底区分形状

| 按钮 | 外观 | 语义 |
|---|---|---|
| **自动运行开关** | 胶囊按钮，图标+文字：`▶ 自动运行`（绿底绿框）/ `⏸ 已停止`（灰） | **持续状态** |
| **手动触发** | 胶囊按钮，闪电图标+文字：`⚡ 运行一次`（中性色） | **一次性执行** |

两者状态互不影响：停止状态下也能点「运行一次」验证流程是否正常。

### 3.4 新增 `PillButton` 样式（`Theme/Styles.xaml`）

`IconButton` 派生自 `GhostButton`，其 Trigger 在 `IsMouseOver` 时会**直接替换**
`Background`，导致"开=绿/关=灰"的状态色一悬停就看不见。
`PillButton` 的 hover 只改 `Opacity`，状态色始终保留。

## 4. 验证（无 UI，真实引擎）

### 4.1 新建流程默认能自动跑

```
新建流程：Enabled=True Paused=False
默认触点：TrigInterval（定时·间隔）
NeedsManualTrigger=False
TodayRunState=今日会运行：无「每天完成」，条件满足即可重复执行
校验 HasError=False

=== 连续 4 次自动扫描 ===
  第1次 Triggered=True  LastRunOk=False
  第2次 Triggered=True  LastRunOk=False
  第3次 Triggered=True  LastRunOk=False
  第4次 Triggered=True  LastRunOk=False

=== 暂停后 ===
  Triggered=False  msg=流程已暂停
```

（`LastRunOk=False` 是因为探针里 A2 会话不在快照中；重点是 `Triggered=True`，
说明**不需要任何手动操作就已经在执行**。）

### 4.2 重启后继续自动跑（真机）

部署 2.17.25 → 重启客户端 → 等 30 秒：

| 流程 | 灯 | LastRunOk | RunCount |
|---|---|---|---|
| db9328b9（已暂停） | 黄 | — | 11（不增长，符合"暂停才停"） |
| 38212a3a | 绿 | True | 882（重启前 881） |
| 6c071938 | 绿 | True | 593（重启前 592） |
