# 云端发布规则

> 本项目所有对外发布**只允许**通过 `scripts/publish-release.ps1` 完成。
> 手工上传、直接改 CDN 文件、绕过脚本的做法一律禁止。

---

## 1. 发布方式的唯一判断依据

| 场景 | 命令 | 说明 |
|---|---|---|
| **首次发布 / 强制全量修复** | `publish-release.ps1 -Full -Push` | 包内含全部程序文件 |
| **常规迭代** | `publish-release.ps1 -Push` | 只含与上版相比**有变化**的文件 |

### 为什么默认是增量

全量包当前约 **123 MB**（Agent 64 MB + Broker 安装器 33 MB + sl-rescue 33 MB）。
绝大多数版本只改主程序（3.4 MB），推全量会让用户每次下载 123 MB。

### 什么时候必须用 `-Full`

1. **首次建立发布通道** —— 用户手里没有 `filelist.json` 的基线。
2. **新增文件** —— 增量包能携带新文件（`filelist.json` 里没有的会自动纳入），
   但如果新增的是一个全新目录结构，建议走全量，避免用户端目录缺失。
3. **删除文件** —— ★ **增量包无法删除文件**。旧文件会残留在用户机器上。
   若要移除某个文件，必须发全量包，且需在更新器里额外实现删除清单
   （目前**未实现**，见第 5 节）。
4. **怀疑用户端文件损坏** —— 全量包可强制覆盖所有文件。

### 增量比对原理

`artifacts/package/filelist.json` 记录上次推送时每个文件的 SHA256。
发布时逐个比对当前文件的哈希：

- 哈希不同 → 纳入增量包
- 哈希相同 → 跳过（即使 build 重新生成了文件、时间戳变了）
- 新文件（清单里没有）→ 纳入
- 清单里有、当前没有 → **警告并列出**，但不会自动删除

清单只在上传**成功之后**才更新。上传失败时清单不前进，
避免下次把「没推上去的文件」当成「已推送」而漏发。

## 2. 打包内容规则

### 包含

```
SoulLink.exe              主程序
SoulLink.Updater.exe      更新器（可自我更新）
agent\SoulLink.Agent.exe  代理
tools\*.exe, *.ps1        服务安装器与脚本
next\*                    辅助工具
7za.exe / sl-rescue.exe   随包工具
```

### 绝对排除（硬性要求）

| 排除项 | 原因 |
|---|---|
| `data\` 整个目录 | **用户配置、账号、备份、日志** —— 覆盖会毁掉用户数据 |
| `stable\` 整个目录 | 挂机测试版，不参与更新 |
| `*.log / *.bak / *.old / *.tmp / *.pdb` | 运行时产物与调试符号 |

> ★ 这条是**不可协商**的。曾经因为把 `data\config.json` 打进包，
> 导致用户升级后所有账号配置被清空的情况必须永不发生。

## 3. 发布顺序（不可颠倒）

```
1. 编辑 docs/RELEASE-NOTES.md   （更新说明，会显示在客户端）
2. 改 SoulLink.csproj 的 <Version>（版本号唯一来源）
3. build.bat                     （生成 dist\ 与 artifacts\dist-<ver>\）
4. publish-release.ps1 -Push     （打包上传刷新 CDN）
```

脚本内部顺序：

```
打包 → 上传 update.zip → HEAD 校验（5 次重试）→ 通过后才写 latest.json → 刷新 CDN
```

**为什么必须先校验 exe 再写清单**：一旦 `latest.json` 指向不可下载的包，
所有用户点「检查更新」都会失败，且**无法自愈**——只能再推一版覆盖。
这条规则来自 ATM 项目的教训，已在本项目固化。

---

## 4. 客户端行为约定

- 启动后 **6 秒**静默检查一次；有新版本时版本号变琥珀色 + 显示红点。
- 点击版本号 → 弹更新窗口（版本对比 + 更新说明 + 确认/取消）。
- 更新失败只显示中性提示（「网络连接失败」等），**不暴露任何发布地址**。
- `cdn.example.invalid` 只允许出现在 `Services/CloudUpdater.cs` 的两个常量里。
  界面上出现该域名属于**缺陷**。

---

## 5. 已知限制（当前未实现）

| 限制 | 影响 | 规避方式 |
|---|---|---|
| **增量包无法删除文件** | 废弃文件残留 | 发全量包；或后续实现删除清单 |
| **无差分/二进制补丁** | 主程序改动 1 行也要下 3.4 MB | 可接受，暂不优化 |
| **无回滚机制** | 推错版本只能再推一版 | `artifacts/dist-<旧版本>\` 保留着历史产物，可手工重推 |
| **更新器未签名** | 可能被杀软拦截 | 用户需手动放行；替换失败会自动回滚 |

---

## 6. 验证清单（每次发布后自查）

```
[ ] latest.json 里的 version 与 csproj 的 <Version> 一致
[ ] CDN 自检通过（脚本会打印 "CDN 已生效"）
[ ] 更新包大小合理（增量通常 < 5 MB，全量约 123 MB）
[ ] zip 内不含 data\ 任何文件
[ ] SoulLink.exe 位于包根（不带 stage\ 前缀）
```

---

## 7. 凭据

COS 凭据来自本机 **COSBrowser 登录态**（%APPDATA%\cosbrowser\），
不写入仓库、不写入脚本、不进入客户端。

临时凭据过期时脚本会尝试 OAuth 刷新；刷新失败需手动重新登录 COSBrowser。
